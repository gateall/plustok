## 1. 목적 (Purpose)

| 목표 | 설명 |
|------|------|
| **멀티프로바이더 지원** | Claude, OpenAI, Gemini, Grok, DeepSeek 단일 API(`ai_call()`)로 통합 |
| **무정지 Failover** | Primary 실패 시 자동 전환 — PLUS톡 V2.0 검증 체인 정형화 |
| **가용성** | Auto 모드 목표 99.99% (5-provider chain) |
| **비용 최적화** | 토큰 사용량·프로바이더별 단가 추적, Admin Dashboard 연동 |
| **응답 표준화** | 프로바이더 무관 `{ ok, text, json, error, usage }` 반환 |
| **운영 통제** | Admin 킬스위치, 단일/Auto 모드, 프로바이더별 키·모델 관리 |

PlusTok 상담원은 고객 메시지마다 AI 추천·감정·계약확률을 실시간 수신한다. AI Router는 이 요청을 안정적으로 처리하는 **플랫폼 핵심 인프라**이다.

## 4. AI 전략 구조

### 4.1 AI Router Decision Tree

```
┌──────────────────────────────────────────────────────────────┐
│              AI Router Decision Tree (Auto Mode)              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│ [1] ai_config() — DB ai_provider_config + ai_settings        │
│     → enabled? OFF → return "AI 전역 킬스위치 OFF"           │
│     → active_provider = 'auto' | 'anthropic' | ...         │
│                                                              │
│ [2] 단일 모드 (provider != 'auto')                           │
│     → api_key 확인 → ai_call_single_provider() → return      │
│                                                              │
│ [3] Auto Failover 체인 시작                                  │
│     failoverChain = [anthropic, openai, gemini, grok,        │
│                       deepseek]                              │
│                                                              │
│     FOR EACH provider:                                       │
│       ├─ api_key 없음 → continue (skip)                      │
│       ├─ ai_call_single_provider(prov)                       │
│       │    ├─ SUCCESS                                        │
│       │    │    ├─ prior failure? → ai_failover_log_insert() │
│       │    │    └─ return { ok: true, ... }                  │
│       │    └─ FAIL                                           │
│       │         ├─ record failedProv, errorCode              │
│       │         └─ NEXT provider                             │
│       └─ (chain exhausted)                                   │
│            → return AI_ALL_FAILED                            │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 Failover 체인 상세 (ai.php 기준)

| 순서 | Provider | DB key | 기본 모델 | 비고 |
|:----:|----------|--------|-----------|------|
| 1 | Anthropic (Claude) | `anthropic` | `claude-opus-4-8` | Primary — 품질·Structured Output |
| 2 | OpenAI (GPT) | `openai` | `gpt-4o` | 2nd — 안정적 Chat Completions |
| 3 | Google Gemini | `gemini` | `gemini-flash-lite-latest` | 3rd — 저비용, 내부 model fallback |
| 4 | xAI Grok | `grok` | `grok-2-latest` | 4th |
| 5 | DeepSeek | `deepseek` | `deepseek-chat` | 5th — PLUS톡 V2.0 확장, 최종 |

> **참고:** 작업지시서 4-provider(Claude→GPT→Gemini→Grok) 명세에 **DeepSeek 5단계**가 `includes/ai.php`에 추가 구현되어 있다. 본 문서는 **런타임(ai.php)을 SSOT**로 한다.

### 4.3 Gemini 내부 Fallback (Provider-Specific)

Gemini는 Failover chain **내부**에서 추가 model fallback을 수행한다:

```
ai_call_gemini()
  modelChain: [configured, gemini-flash-lite-latest,
              gemini-3.1-flash-lite, gemma-4-31b-it, gemini-flash-latest]
  FOR EACH model:
    attempt 1..2:
      429/503/timeout → usleep(1s) → retry
  → 모두 실패 시 chain 다음 provider (OpenAI/Grok/...)로 Failover
```

### 4.5 ai_config() 로드 순서

```
1. config/ai.php 파일 로드 (base: timeout, api_url, max_tokens)
2. DB ai_provider_config id=1 → active_provider, enabled
3. IF provider != 'auto':
     DB ai_settings WHERE provider = active → api_key, model
4. IF DB 오류 → 파일 설정 폴백 (catch Throwable)
5. static 캐시 ($forceReload=true 시 무시)
```

## 7. Business Rule

### 7.1 AI Router 규칙 (Rule-001)

| # | 규칙 | 상세 |
|---|------|------|
| BR-001 | 활성 프로바이더 | Auto: Claude → OpenAI → Gemini → Grok → DeepSeek |
| BR-002 | Admin 변경 | `active_provider` 즉시 반영 (`ai_config` static cache 주의) |
| BR-003 | Failover 조건 | Timeout, HTTP 429/5xx, curl fail, invalid response |
| BR-004 | 재시도 | Provider chain 최대 5회 (각 1회) + Gemini 내부 retry |
| BR-005 | API Key 없음 | chain skip (Failover 아님) |
| BR-006 | 킬스위치 | `enabled=false` → 즉시 error, chain 미실행 |

### 7.2 Failover 트리거 조건

| 조건 | error_code | ai.php 감지 |
|------|------------|-------------|
| HTTP timeout | `TIMEOUT` | `stripos($error, 'timeout')` |
| HTTP 429 | `429` | `preg_match('/HTTP\s+([0-9]{3})/')` |
| HTTP 5xx | `500`~`599` | HTTP status ≥ 400 |
| curl 실패 | `ERROR` | `$raw === false` |
| 전체 실패 | `AI_ALL_FAILED` | chain exhausted |

### 7.3 Rate Limiting (Rule-005)

| Provider (참고) | 분당 요청 | 초과 시 |
|-----------------|-----------|---------|
| Claude | 100 | 429 → Failover |
| OpenAI | 50 | 429 → Failover |
| Gemini | 60 | 429 → Failover + 내부 retry |
| Grok | 40 | 429 → Failover |
| **Room (ACEP)** | **10/min** | Redis `rl:ai:room:{id}` |

현재 구현: `ai_check_rate_limit()` — Session 30초 debounce. Production: Redis Rule-005.

### 7.4 캐싱 전략 (MASTER PART 5.5)

| AI 역할 | TTL | Redis Key |
|---------|-----|-----------|
| 답변추천 | 1시간 | `ai:rec:{roomId}:{msgHash}` |
| FAQ 검색 | 24시간 | `ai:faq:{embeddingHash}` |
| 계약확률 | **없음** | 매 메시지 재계산 |
| 상담요약 | 상담 종료까지 | `ai:sum:{roomId}` |
| 감정 | **없음** | 실시간 |

상세: [03_AI엔진구현.md](03_AI엔진구현.md) §5

## 8. AI Rule

### 8.1 프롬프트 선택

- `request_type` / `feature`별 다른 프롬프트 ([02_Prompt설계.md](02_Prompt설계.md))
- 버전 지정 가능 (기본: `is_active=1` latest)
- DB `ai_prompts`에서 로드

### 8.2 개인정보 마스킹 (Rule-007)

| 유형 | 마스킹 결과 |
|------|-------------|
| 이메일 | `use***@domain.com` |
| 휴대전화 | `010-****-5678` |
| 상세주소 | `[상세주소 마스킹]` |
| 고객명 | **마스킹 안 함** (상담 맥락 유지) |

→ AI 호출 **전** `ai_mask_pii()` 필수

### 8.3 응답 정규화

모든 provider → `ai_call()` 표준 반환:

```php
['ok' => bool, 'text' => string, 'json' => ?array,
 'error' => ?string, 'usage' => ['input_tokens'=>int, 'output_tokens'=>int]]
```

### 8.4 토큰 추적 및 비용

| 단계 | 처리 |
|------|------|
| 호출 시 | `ai_log()` → `input_tokens`, `output_tokens`, `duration_ms` |
| 집계 | Admin Dashboard KPI — [00_PROJECT_MASTER.md](../00_PROJECT_MASTER.md) PART 5.1 |
| 비용 계산 | provider별 요금표 × token (V2.5 ML Ops Center) |
| 예산 알림 | 월 한도 설정 (V2.0) |

**비용 추정 공식 (참고):**

```
cost_usd = (input_tokens / 1_000_000) * input_price
         + (output_tokens / 1_000_000) * output_price
```

Admin Dashboard `ai_logs` 집계 쿼리:

```sql
SELECT provider, model,
       SUM(input_tokens) AS total_in,
       SUM(output_tokens) AS total_out,
       COUNT(*) AS calls,
       AVG(duration_ms) AS avg_ms
FROM ai_logs
WHERE created_at >= CURDATE()
  AND status = 'ok'
GROUP BY provider, model;
```

## 부록 B. 모니터링 쿼리 (Operator)

```sql
-- 최근 24h Failover 빈도
SELECT failed_provider, fallback_provider, error_code, COUNT(*) AS cnt
FROM ai_failover_log
WHERE created_at >= NOW() - INTERVAL 24 HOUR
GROUP BY failed_provider, fallback_provider, error_code
ORDER BY cnt DESC;

-- Provider별 에러율
SELECT provider, status, COUNT(*) AS cnt, AVG(duration_ms) AS avg_ms
FROM ai_logs
WHERE created_at >= NOW() - INTERVAL 24 HOUR
GROUP BY provider, status;
```
