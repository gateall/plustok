## 1. 테스트 피라미드 (Test Pyramid)

### 1.1 계층 구조

```
                    ┌─────────────────┐
                    │   E2E / Manual  │  ~10% effort
                    │  (핵심 사용자   │  Release gate
                    │   여정 5 flows) │
                    ├─────────────────┤
                    │  Integration    │  ~30% effort
                    │  REST 40 APIs   │  CI nightly
                    │  WebSocket 10   │
                    ├─────────────────┤
                    │   Unit Tests    │  ~60% effort
                    │  PHP Services   │  CI every PR
                    │  Node handlers  │
                    │  React 11 comp  │
                    └─────────────────┘
```

### 1.2 계층별 정의

| 계층 | 대상 | 도구 | 실행 시점 | 목표 |
|------|------|------|-----------|------|
| **Unit** | Service, Repository, Pure functions, React components/hooks | PHPUnit, Vitest, Jest (Node) | PR merge 전 (CI) | Line coverage ≥ 80% (Service/Repository) |
| **Integration** | REST API, WebSocket events, DB transactions | PHPUnit + Test DB, Supertest, socket.io-client | Nightly + pre-release | 100% endpoint/event coverage |
| **E2E** | Full user journeys, Admin flows, Cross-browser smoke | Manual QA + checklist (V1.0) | Staging, pre-release | Critical path 100% pass |

### 1.3 V1.0 vs V1.5+ 자동화 로드맵

| 버전 | Unit/Integration | E2E |
|------|------------------|-----|
| V1.0 MVP | CI 필수 (PHPUnit + Vitest + API collection) | **수동 QA** 체크리스트 |
| V1.5 | + WS integration harness in CI | Playwright pilot (Agent flow) |
| V2.0 | Contract tests (OpenAPI) | Playwright full regression suite |

## 2. 커버리지 목표 (MASTER PART 8.4)

### 2.1 정량 목표

| 유형 | MASTER 기준 | ACEP 측정 방법 | Gate |
|------|-------------|----------------|------|
| 단위 테스트 | **80% 이상** (Service, Repository) | PHPUnit `--coverage-text`, Vitest `coverage` | PR merge block if < 75% |
| 통합 테스트 | **모든 REST API** + WebSocket 이벤트 | Newman/Postman + custom WS test runner | Release block if any fail |
| E2E | 접수→채팅→AI추천→종료→CRM | [03_E2E](03_E2E_시나리오_및_체크리스트.md) E2E-01 | Sign-off required |
| UI TC | [TC-001~007](../02_UIUX/01_상담채팅화면.fig.md) | Manual execution log | 100% pass (P0/P1) |

### 2.2 성능·가용성 SLA (테스트 검증 대상)

| 지표 | MASTER 목표 | 테스트 방법 | 환경 |
|------|-------------|-------------|------|
| WS 메시지 지연 | 0.1초 이내 | Chrome DevTools + timestamp diff | Staging |
| AI 추천 표시 | 2초 이내 | E2E stopwatch / API latency log | Staging (mock AI) |
| REST API p95 | 1초 이내 | k6/Artillery smoke (optional) | Staging |
| 페이지 초기 로드 | 3초 이내 | Lighthouse CI (optional) | Staging |
| 동시 WS 연결 | 1,000+ | Load test **staging only** | Staging |
| AI Failover 성공률 | 99.9% (post-failover) | FO-001~007 + TC-006 | Staging |

### 2.3 커버리지 제외 (Exclusions)

| 대상 | 사유 |
|------|------|
| `vendor/`, `node_modules/` | Third-party |
| Legacy CRM PHP (non-ACEP paths) | Out of MVP scope |
| Config/bootstrap one-liners | Low risk |
| Generated migration stubs | DB tool output |
| `embed/embed.js` legacy | Regression only on change |

## 8. 회귀 테스트 정책 (Regression Policy)

### 8.1 트리거

| Event | Regression Scope | SLA |
|-------|------------------|-----|
| PR merge to `develop` | Unit + affected integration | CI < 10 min |
| Nightly build | Full integration (40 APIs) | < 30 min |
| Pre-release tag | Full E2E checklist P0/P1 | 2 QA days |
| Hotfix | P0 TC + changed module | 4 hours |
| `admin/settings/ai.php` change | TC-ADM-I* + ai.php regression | Same day |

### 8.2 회귀 Tier

| Tier | TC Set | Count | When |
|------|--------|-------|------|
| **P0 Smoke** | E2E-01, TC-001, TC-002, TC-ADM-A01, health | ~15 | Every deploy |
| **P1 Core** | IT-01~72, TC-003~007, TC-ADM-D/M | ~80 | Weekly / pre-release |
| **P2 Full** | All TC-ADM-*, FO-*, TC-WS-* | ~150 | Major release |
| **P3 Extended** | Performance, edge cases | ~50 | V1.5+ |

### 8.3 Legacy Regression (PLUS톡 V2.0)

| Area | Test | Reason |
|------|------|--------|
| `includes/ai.php` | FO-001~007 | Failover SoT |
| `admin/settings/ai.php` | TC-ADM-I01~05 | Existing production page |
| CRM consult list | TC-ADM-C01 | UNION chat_rooms |
| Embed widget | Smoke load | Customer entry |

### 8.4 회귀 실패 처리

```
Regression fail detected
    ↓
QA logs bug (severity per §03)
    ↓
P0/P1 → release block
P2 → Known Issue + waiver (Release Manager)
    ↓
Fix → re-run failed tier only
    ↓
Pass → update sign-off
```

## 12. 리스크 및 완화
