### PART 5. AI Strategy (2~3페이지)
**목적:** AI가 무엇을 하는가 (매우 중요)

**AI 역할 10가지:**

```
1. 상담요약 (Summarization)
   └─ 고객 대화를 간단하게 요약
   └─ 상담원이 빠르게 상황 파악

2. 고객분석 (Customer Analysis)
   └─ 고객 배경, 관심사, 구매 의사 분석
   └─ 고객 프로필 자동 작성

3. 감정분석 (Sentiment Analysis)
   └─ 고객 감정 파악 (긍정/중립/부정)
   └─ 불만 고객 즉시 발견

4. 계약확률 (Contract Probability)
   └─ 고객의 구매 가능성 0~100점 산출
   └─ 우선순위 자동 결정

5. 답변추천 (Answer Recommendation)
   └─ 상담원이 답할 내용 제시
   └─ 1클릭으로 전송

6. FAQ 검색 (FAQ Search)
   └─ 질문과 유사한 FAQ 자동 검색
   └─ 해답 제시

7. 문서검색 (Document Search)
   └─ 가격표, 상품 자료, 계약서 검색
   └─ 빠른 참조 가능

8. 상품추천 (Product Recommendation)
   └─ 고객 문의에 맞는 상품 추천
   └─ Cross-selling 기회 제시

9. 일정생성 (Appointment Generation)
   └─ 상담 후 후속 일정 자동 생성
   └─ 캘린더에 등록

10. CRM 기록 (CRM Recording)
    └─ 상담 내용 자동으로 CRM에 저장
    └─ 수작업 제거
```

**AI 실행 흐름:**

```
고객 메시지 수신
    ↓
AI Router (활성 AI 선택)
    ↓
Claude 호출 (기본, timeout: 10초)
    ↓ 실패 (timeout/rate limit/error)
GPT 호출 (timeout: 10초)
    ↓ 실패
Gemini 호출 (timeout: 10초)
    ↓ 실패
Grok 호출 (timeout: 10초)
    ↓
응답 반환 (또는 실패 응답)
    ↓
상담원 화면에 표시
    ↓
상담원 클릭 → 고객에게 전송
    ↓
CRM 자동 저장
```

### PART 7. AI Rule (1~2페이지)
**목적:** AI 사용 규칙 (매우 중요)

**포함 내용:**

```
Rule-001: AI Router Failover
┌──────────────────────────────────────────┐
│ 활성 AI가 실패하면 자동으로 다음 AI로  │
├──────────────────────────────────────────┤
│ 1단계: Claude (기본)                     │
│        timeout: 10초, max_tokens: 1024   │
│ 2단계: OpenAI GPT (Claude 실패 시)      │
│        timeout: 10초, model: gpt-4       │
│ 3단계: Google Gemini (GPT 실패 시)      │
│        timeout: 10초                     │
│ 4단계: xAI Grok (Gemini 실패 시)        │
│        timeout: 10초                     │
│ 5단계: 실패 응답 (모두 실패 시)         │
│        "AI 분석 불가. 나중에 다시..."   │
│                                          │
│ 로그: ai_failover_log 테이블에 기록     │
│ 캐싱: 1시간 (같은 질문 반복 시)        │
└──────────────────────────────────────────┘

Rule-002: Prompt Versioning
- 모든 Prompt는 버전 관리 (v1.0, v1.1, v1.2, ...)
- prompts 테이블에 저장
- 변경 이력 기록 (날짜, 변경자, 변경 내용)
- Rollback 가능하도록 설계
- 테스트 환경에서 v1.1→v1.0 비교 검증

Rule-003: API Key Management
- 환경변수로 관리 (.env 파일)
- 코드에 하드코딩 금지
- 각 AI별로 별도 저장 (ai_keys 테이블)
- 정기적 로테이션 (월 1회)
- 접근 로그 기록 (ai_key_log)

Rule-004: Rate Limiting
- IP당 분당 100 요청 제한
- 사용자당 분당 50 요청 제한
- AI 호출당 분당 30 요청 제한 (비용 관리)
- 초과 시 429 Too Many Requests 응답
- Redis로 관리

Rule-005: Response Format
- API 응답: {success: true, data: {...}, timestamp: "..."}
- 에러 응답: {success: false, error: "...", code: "ERR_001"}
- WebSocket 메시지: {type: "...", payload: {...}}
- 항상 타임스탬프 포함
```

### PART 9. Security (1페이지)
**목적:** 보안 기준

**포함 내용:**

```
인증
- JWT 토큰 (유효기간 24시간)

- 로그인 3회 실패 시 계정 잠금 (1시간)

- 관리자: 전체 조회

개인정보 보호
- 전화번호: 뒷자리 마스킹 (010-****-5678)
- 이메일: 일부 마스킹 (user@****.com)
- 주소: 뒷부분 마스킹 (서울시 강남구 ****)
- AES-256 암호화 저장
- GDPR, CCPA 준수

데이터 통신
- HTTPS 필수
```

### 7. Business Rule

```
읽음 표시 규칙:
- 메시지 수신 즉시: ✓ (1개)
- 메시지 클릭/표시 시: ✓✓ (2개)
- UI에 시간 표시: "✓✓ 2026-07-21 14:31"
- 자동 표시 안 함 (사용자 선택)

입력 중 표시:
- 사용자가 입력 시작하면 상대방에게 표시
- "입력 중..." 텍스트 + 점 애니메이션
- 3초간 입력 없으면 사라짐
- 전송 완료 시 즉시 사라짐

AI 추천 트리거:
- 고객 메시지 수신 즉시
- 최대 2초 내에 표시
- 실패 시 "분석 중..." 표시
- 최대 3개 추천 표시
- 캐싱: 동일 질문 1시간

상담 종료 프로세스:
- "상담종료" 버튼 클릭
- 확인 모달 표시 (정말 종료?)
- 자동으로:
  1. 상담요약 생성 (3초)
  2. CRM 저장 (1초)
  3. 후속일정 제안 (2초)
  4. 만족도 조사 모달 표시
  5. 상담 상태 = 종료로 변경
```

### 8. AI Rule

```
추천답변 생성:
- Prompt: "이 고객 질문에 대한 최선의 답변 3개를 작성하시오. 각 50자 이내."
- 모델: Claude Sonnet (비용 최적화)
- 실패 시 자동 Failover (GPT → Gemini → Grok)
- 캐싱: 동일 질문 1시간

FAQ 검색:
- 고객 질문을 Embedding (Claude)
- FAQ 테이블과 Cosine Similarity 계산
- 상위 3개 표시 (유사도 70% 이상)

계약확률 계산:
- 고객정보 + 대화 내용 분석
- 0~100점 산출 (Claude 분석)
- 실시간 업데이트 (메시지마다)
- 색상: 0-33=빨강, 34-66=주황, 67-100=초록

고객분석:
- 감정: 긍정/중립/부정 분류
- 의도: 구매/문의/불만 분류
- 배경: 신규/기존/위험 고객 분류
- 자동 태그 생성 (예: #긍정 #구매의사높음)
```

### 9. Exception

```
오류 처리:
- 메시지 전송 실패: "전송 실패 [재시도]" 버튼 표시
- AI 응답 지연(5초): "분석 중..." → "분석 완료" 또는 "분석 실패"
- AI 응답 실패: "AI 분석 불가. 나중에 다시 시도해주세요"
- 네트워크 끊김: "재연결 중..." 표시 + 자동 재연결
- 파일 업로드 실패: 오류 메시지 + "다시 시도" 버튼

타임아웃:
- 메시지 전송: 10초 (실패 처리)
- AI 추천: 5초 (자동 숨김)
- 읽음표시: 3초

재시도:
- 자동 재시도: 3회 (exponential backoff)
- 수동 재시도: 버튼으로 제공
```
