# 작업지시서: 문의 채널별 콜백 알림 + Render Keep-Alive (2026-07-22)

**상태:** 설계 의도 정리 — 구현 필요
**우선순위:** Keep-Alive > 콜백 알림 (콜백은 채널 결정 필요, Keep-Alive는 바로 착수 가능)

---

## 1. Render Keep-Alive 핑 (바로 착수 가능)

### 의도 (왜)
`chat-server`(Render 무료 플랜)는 약 15분간 요청이 없으면 슬립되고, 다음 요청 시 최대 1분 가까이 콜드스타트가 걸린다. 이 동안 상담원이 채팅 화면(`/frontend/#/chat`)을 열면 WebSocket 연결이 "재연결 중..."을 반복하다가 뒤늦게 붙는 문제가 있다. 무료 플랜을 계속 쓸 거라면, 슬립 자체를 막아야 한다.

### 요구사항
- **외부(Render 밖)**에서 주기적으로(10~14분 간격, 15분 미만 필수) `https://plustok.onrender.com/health`에 GET 요청을 보내 슬립을 방지
- Render 자체에는 크론 기능이 없으므로(무료 플랜), 외부 트리거 필요:
  - 예: cron-job.org, UptimeRobot, GitHub Actions scheduled workflow, 또는 Cafe24 서버의 크론(가능하면)에서 curl 한 줄
- 응답이 `{"status":"healthy",...}` 인지까지 확인할 필요는 없음 — 요청 자체가 슬립을 막는 목적이므로 실패해도 무해 (알림/재시도 불필요)

### 완료 기준
- [ ] 10~14분 주기로 `/health`를 호출하는 외부 스케줄러 설정 완료
- [ ] 1시간 이상 방치 후 `/frontend/#/chat` 최초 진입 시 "재연결 중" 없이 바로 연결되는지 확인

## 2. 문의 채널별 콜백 알림 (설계 의도만 — 세부 구현은 보류 항목 있음)

### 의도 (왜)
고객이 상담을 신청하면(`consults` 생성), 관리자는 이미 이메일로 알림을 받는다(`ADMIN_NOTIFY_EMAIL`, 오늘 연결 완료). 그런데 실제 "콜백"(고객에게 다시 연락하는 채널)은 **고객이 문의에 남긴 연락 수단과 일치**해야 한다는 것이 사용자 의도다:

> 메일로 문의 → 메일로 콜백
> 폰(전화/문자)으로 문의 → 폰으로 콜백

즉, 상담 접수 데이터(`consults`/`customers`: `email`, `phone`)를 보고 고객이 **어느 채널로 연락받길 원하는지**를 관리자 화면과 알림에 명확히 드러내고, 그에 맞는 콜백 액션(메일 회신 or 전화/문자 발신)을 상담원이 바로 취할 수 있게 해야 한다.

### 현재 상태
- `embed/embed.js` 폼은 `phone`(필수) + `email`(선택)을 모두 받음 → 이메일이 없는 고객이 다수일 수 있음
- 관리자 알림 메일(`notify_new_consult()`)은 이미 연락처(`phone`)와 이메일이 있으면 이메일도 본문에 포함하고 있음 (`includes/functions.php:146`)
- **고객에게 보내는** 콜백(메일 회신 자동화, SMS/카카오 발신)은 아직 없음

### 구현 방향 (제안 — 확정 아님, 아래 결정 필요)

1. **이메일 콜백** (고객이 email을 남긴 경우)
   - 상담원이 `admin/consults/view.php`에서 "AI 답변 초안 생성" 결과를 그대로 **고객 이메일로 발송**하는 버튼 추가 (기존 `acep_send_mail()` 재사용 가능)
   - 조건: `customers.email`이 있을 때만 이 버튼 노출

2. **폰 콜백** (email이 없거나 phone 중심인 경우)
   - 최소: 상담원이 전화 걸기 편하도록 전화번호를 클릭 가능한 `tel:` 링크로 표시 (이미 되어 있을 수 있음, 확인 필요)
   - 확장(선택): SMS 또는 카카오 알림톡으로 자동 콜백 메시지 발송 — **이건 외부 유료 서비스 계정이 있어야 진행 가능** (예: 알리고, NHN Toast, 카카오 비즈메시지 중 택1). 계정/API 키 없으면 이 항목은 보류.

### 결정 필요 (사용자 확인 후 진행)
- [ ] SMS/카카오 자동 발송까지 할 것인지, 아니면 "상담원이 전화로 직접 콜백"까지만 지원할 것인지
- [ ] SMS/카카오 자동 발송을 원한다면 어떤 서비스 계정을 쓸지 (계정/API 키 필요)

### 완료 기준 (1차 — 이메일 콜백만)
- [ ] `customers.email` 있는 상담 건에 한해 `admin/consults/view.php`에 "이메일로 답변 발송" 버튼 노출
- [ ] 버튼 클릭 시 AI 답변 초안(또는 직접 입력) 내용을 고객 이메일로 발송, 발송 이력 남김(`consult_history` 또는 별도 로그)
