## 1. 목표와 범위

### 1.1 목표

상담원(Operator)과 관리자(Admin)가 **채팅·AI·CRM 연계 지표**를 한 화면에서 확인하고,
이상 징후(Failover 급증, CRM 저장 실패, SLA 초과)를 **수 분 이내**에 감지한다.

| 이해관계자 | 필요 정보 | 갱신 주기 |
|-----------|----------|----------|
| Operator | 내 담당 방·대기열·AI 추천 채택 | 5~10초 |
| Admin | 전체 KPI·상담원 랭킹·감성·퍼널 | 30~60초 |
| Live Monitor | 전광판용 대형 KPI·Failover ticker | 5초 (WS) |

### 1.2 In Scope (본 문서)

- `StatsAggregator` 배치·온디맨드 집계 규칙
- Redis 키 설계·TTL·무효화
- `GET /api/v1/admin/stats/*` 데이터 계약 (개요만; JSON 스키마 상세는 07_ADMIN)
- HTTP 폴링 → Socket.io `admin` namespace (V1.5)
- Chart.js 4 및 React V2.0에서 동일 API 재사용 원칙

### 1.3 Out of Scope

- 고객 포털 `/customer/dashboard` → [01_고객대시보드.md](01_고객대시보드.md)
- Admin RBAC·에이전트 CRUD → [07_ADMIN/02_상담원관리.md](../07_ADMIN/02_상담원관리.md)
- WebSocket 채팅 이벤트 → [05_CHAT/01_WebSocket설계.md](../05_CHAT/01_WebSocket설계.md)

### 2.2 데이터 흐름 (Happy Path)

1. **집계:** `StatsAggregator`가 30초마다 `overview`·`agents` 스냅샷을 Redis에 기록.
2. **조회:** Admin UI가 `GET /stats/overview` 호출 → Controller가 Redis HIT → JSON 반환 (< 50ms).
3. **미스:** Redis MISS 시 Aggregator SQL을 동기 실행(타임아웃 2s) 후 캐시 warming.
4. **V1.5:** 동일 스냅샷 변경분을 `stats:delta` 이벤트로 push → 클라이언트는 KPI DOM만 patch.

### 2.3 버전별 전송 계층

| 버전 | Transport | 클라이언트 | 비고 |
|------|-----------|-----------|------|
| V1.0 | HTTP poll 5/10/30/60s | PHP `admin/index.php` + Chart.js | 기본 배포 |
| V1.5 | + WS `/admin` | partial DOM update | Failover·KPI 실시간 |
| V2.0 | 동일 API | `06_FRONTEND` React SPA | SSE fallback |

## 3. StatsAggregator

### 3.1 책임

- KPI SQL 실행·결과 정규화(JSON serializable)
- Redis 키 write·TTL 설정
- (V1.5) 변경 감지 시 Socket.io publish
- 집계 실패 시 **stale cache 유지** + `stats_agg_error` 메트릭

### 3.2 실행 트리거

| 트리거 | 주기 | 대상 키 |
|--------|------|---------|
| systemd timer `plustok-stats-overview` | 30s | `admin:stats:overview:{date}` |
| cron `*/1 * * * *` | 60s | sentiment, funnel |
| cron `*/5 * * * *` | 5min | trends (hourly rollups) |
| HTTP cache miss | on-demand | 요청된 키만 |
| `message.created` hook (optional) | event | active_chats bump |

### 3.3 PHP 진입점 (예시)

```php
// cli: php artisan stats:aggregate --scope=overview
class StatsAggregator {
  public function run(string $scope, \DateTimeInterface $asOf): array {
    $sql = $this->registry->sqlFor($scope);
    $rows = $this->db->fetchAll($sql, $this->bindPeriod($asOf));
    $payload = $this->normalizer->toOverview($rows);
    $this->redis->setex($this->cacheKey($scope, $asOf), 30, json_encode($payload));
    return $payload;
  }
}
```

### 3.4 타임존·기간

- 모든 `DATE()`/`CURDATE()`는 **Asia/Seoul** (BR-DASH-001).
- API `period` 파라미터: `today` | `7d` | `30d` | `custom` (max 90d, BR-DASH-005).

## 4. Redis 캐시 계층

### 4.1 키 네이밍

| 키 패턴 | TTL | 내용 |
|---------|-----|------|
| `admin:stats:overview:{Y-m-d}:{period}` | 30s | KPI 4-pack + sparkline arrays |
| `admin:stats:sentiment:{period}` | 60s | positive/neutral/negative counts |
| `admin:stats:funnel:{period}` | 60s | adoption buckets |
| `admin:stats:agents:{Y-m-d}` | 30s | top 10 agents |
| `admin:stats:trends:{period}:{granularity}` | 300s | hourly/daily series |
| `admin:stats:meta:last_ok` | — | last successful aggregate ISO8601 |

### 4.2 무효화

- 자정 KST: `admin:stats:*:{previous_date}*` 는 lazy expire (TTL로 충분).
- Admin이 `period=custom` 요청 시 해당 period 해시만 MISS 허용; overview today는 핫 패스.

### 4.3 Redis Down 시

→ [13장](#13-장애성능폴백) 참조. Controller는 MariaDB direct + circuit breaker.

## 6. KPI 파이프라인 상세

각 KPI는 **원천 테이블 → Aggregator SQL → Redis → API 필드**로 1:1 매핑한다.

### 6.1 chat_rooms 파이프라인

| KPI ID | 이름 | 정의 | API 필드 |
|--------|------|------|----------|
| KPI-01 | 활성 상담 | status IN (active, waiting) | `overview.active_chats` |
| KPI-02 | 오늘 종료 | status=closed AND closed_at 오늘 | `overview.closed_today` |
| KPI-05 | CRM 저장 실패 | crm_save_status=failed (24h) | `widgets.crm_fail_count` |
| KPI-06 | VIP 대기 | priority=vip AND status=waiting | `widgets.vip_waiting` |

**집계 주의:** `deleted_at IS NULL` 필수. Operator 뷰는 `assigned_agent_id = :me` 필터 추가.

### 6.2 messages 파이프라인

| KPI ID | 이름 | 정의 |
|--------|------|------|
| KPI-07 | 오늘 메시지 수 | created_at >= today KST |
| KPI-08 | 첫 응답 SLA | operator 첫 메시지까지 초 (P95) |
| KPI-09 | 고객 대기 중 | 마지막 sender_type=customer & status active |

SLA는 방 단위 서브쿼리 후 P95; sparkline은 시간대별 COUNT.

### 6.3 ai_logs 파이프라인

| KPI ID | 이름 | 정의 |
|--------|------|------|
| KPI-10 | AI 호출 수 | count(*) per period |
| KPI-11 | 감성 분포 | group by sentiment |
| KPI-12 | Latency P95 | percentile(latency_ms, 0.95) |

`sentiment` NULL은 neutral로 bucket (BR-DASH-004: 빈 데이터는 N/A).

### 6.4 ai_recommendations 파이프라인

| KPI ID | 이름 | 정의 |
|--------|------|------|
| KPI-13 | 추천 생성 수 | count per period |
| KPI-14 | 채택률 | SUM(used=1)/COUNT(*) * 100 |
| KPI-15 | 퍼널 버킷 | 채택률 구간별 room 수 |

퍼널 API `/stats/funnel`과 동일 SQL.

### 6.5 ai_failover_log 파이프라인

Live Monitor ticker 및 Block 5 위젯:

- 1h rolling count by `to_provider`
- spike rule: >10/h → alert `dashboard_failover_spike`

### 6.6 agents 파이프라인

| KPI ID | 이름 | 정의 |
|--------|------|------|
| KPI-16 | 온라인 상담원 | agents.status=online |
| KPI-17 | 상담원별 종료 | join chat_rooms closed today |
| KPI-18 | 평균 처리 시간 | avg(closed_at - assigned_at) |

`/stats/agents` limit 10, sort `closed_today DESC`.

### 6.2 파이프라인 시퀀스 (ASCII)

```
chat_rooms ──► KPI-01,02,05,06 ──┐
messages   ──► KPI-07,08,09 ─────┼──► StatsAggregator ──► Redis ──► REST/WS
ai_logs    ──► KPI-10,11,12 ─────┤
ai_recommendations ─ KPI-13-15 ──┤
ai_failover_log ───► widgets ────┤
agents     ──► KPI-16-18 ────────┘
```

## 7. 폴링 간격과 V1.5 WebSocket

### 7.1 V1.0 HTTP 폴링 매트릭스

| UI 영역 | interval | endpoint | 근거 |
|---------|----------|----------|------|
| KPI 카드 | 60s | `/stats/overview` | 변경 빈도 낮음, Redis 30s TTL |
| Agent 테이블 | 300s (5min) | `/stats/agents` | DB 부하 |
| 감성·퍼널 차트 | 60s | `/stats/sentiment`, `/stats/funnel` | Chart.js redraw 비용 |
| Live Failover | 30s | overview subset 또는 dedicated | 운영 민감 |
| Live Monitor 전광판 | 5s | `/stats/overview` (light) | 별도 read-only token |
| Sparkline | 60s | overview 내 embedded arrays | 추가 RTT 방지 |

Operator 대시보드는 KPI 5s + agents 10s로 **더 aggressive** (담당 방만 필터).

### 7.2 클라이언트 구현 (V1.0)

```javascript
// admin/assets/dashboard.js
const POLL = {
  overview: 60000,
  agents: 300000,

```

`document.visibilityState === 'hidden'` 이면 interval 2배 (배터리·부하).

### 7.3 V1.5 WebSocket admin namespace

**Namespace:** `/admin` (JWT role admin|operator|monitor)

| Event | Payload | UI 동작 |
|-------|---------|---------|
| `stats:delta` | `{ metric, value, delta_pct }` | KPI card text update |
| `stats:sparkline` | `{ metric, points[] }` | canvas partial |
| `failover:new` | `{ provider, reason }` | ticker prepend |
| `room:update` | room summary | agent table row |

**Subscribe:** `socket.emit('subscribe:dashboard', { period: 'today' })`

마이그레이션: V1.0 poll 유지 + WS 연결 성공 시 poll interval 2x 완화 → 안정 후 poll 제거(KPI만).

### 7.4 V1.5 서버 publish

Aggregator 또는 Chat Server hook:

```javascript

```

Room naming: `dashboard:{period}` + operator는 `dashboard:agent:{id}`.

## 12. KPI별 SQL 예시

> 프로덕션에서는 prepared statement·read replica 권장.

### 12.1 KPI-01 활성 상담

```sql
SELECT COUNT(*) AS active_chats
FROM chat_rooms
WHERE deleted_at IS NULL
  AND status IN ('active', 'waiting');
```

### 12.2 KPI-02 오늘 종료

```sql
SELECT COUNT(*) AS closed_today
FROM chat_rooms
WHERE deleted_at IS NULL
  AND status = 'closed'
  AND CONVERT_TZ(closed_at, '+00:00', '+09:00') >= CURDATE();
```

### 12.3 KPI-14 AI 추천 채택률

```sql
SELECT ROUND(100.0 * SUM(CASE WHEN used = 1 THEN 1 ELSE 0 END) / NULLIF(COUNT(*), 0), 1) AS adoption_pct
FROM ai_recommendations
WHERE created_at >= :period_start AND created_at < :period_end;
```

### 12.4 KPI-11 감성 분포

```sql
SELECT COALESCE(sentiment, 'neutral') AS sentiment, COUNT(*) AS cnt
FROM ai_logs
WHERE created_at >= :period_start AND created_at < :period_end
GROUP BY COALESCE(sentiment, 'neutral');
```

### 12.5 KPI-08 첫 응답 SLA (P95)

```sql
SELECT PERCENTILE_CONT(0.95) WITHIN GROUP (ORDER BY fr_sec) AS p95_first_response
FROM (
  SELECT TIMESTAMPDIFF(SECOND, r.created_at, MIN(m.created_at)) AS fr_sec
  FROM chat_rooms r
  JOIN messages m ON m.chat_room_id = r.id AND m.sender_type = 'operator'
  WHERE r.created_at >= :period_start
  GROUP BY r.id
) t;
```

(MariaDB 10.3+ 없으면 앱 레이어 percentile 근사.)

### 12.6 KPI-17 상담원별 종료 (Top N)

```sql
SELECT a.id, a.display_name,
       COUNT(r.id) AS closed_today,
       AVG(TIMESTAMPDIFF(MINUTE, r.assigned_at, r.closed_at)) AS avg_handle_min
FROM agents a
LEFT JOIN chat_rooms r ON r.assigned_agent_id = a.id
  AND r.status = 'closed'
  AND DATE(CONVERT_TZ(r.closed_at, '+00:00', '+09:00')) = CURDATE()
WHERE a.deleted_at IS NULL
GROUP BY a.id, a.display_name
ORDER BY closed_today DESC
LIMIT 10;
```

### 12.7 Failover 1h rolling

```sql
SELECT to_provider, COUNT(*) AS cnt
FROM ai_failover_log
WHERE created_at >= NOW() - INTERVAL 1 HOUR
GROUP BY to_provider
ORDER BY cnt DESC;
```

### 12.8 CRM 저장 실패 (24h)

```sql
SELECT COUNT(*) AS crm_fail_count
FROM chat_rooms
WHERE crm_save_status = 'failed'
  AND updated_at >= NOW() - INTERVAL 24 HOUR;
```

### 12.9 Hourly trends

```sql
SELECT DATE_FORMAT(CONVERT_TZ(created_at, '+00:00', '+09:00'), '%Y-%m-%d %H:00') AS bucket,
       COUNT(*) AS msg_cnt
FROM messages
WHERE created_at >= :period_start
GROUP BY bucket
ORDER BY bucket;
```

SELECT COUNT(*) FROM chat_rooms
WHERE assigned_agent_id = :agent_id
  AND status IN ('active', 'waiting')
  AND deleted_at IS NULL;

## 13. 장애·성능·폴백

### 13.1 Redis Down

1. Controller: `Redis::ping` fail → `stats_redis_down` metric + **DB direct path**
2. Circuit breaker: 30s 동안 Redis 재시도 중단
3. 응답 헤더 `X-Stats-Cache: bypass`
4. TTL 없음 → SLA KPI p95 500ms → 2s까지 허용, UI banner "캐시 없음"

### 13.2 WebSocket Fail (V1.5)

1. `socket.on('disconnect')` → exponential backoff reconnect
2. 3회 실패 → **V1.0 poll로 degrade** (overview 30s)
3. UI badge "실시간 연결 끊김"

### 13.3 API 504 / 5xx

- KPI `?` + retry button (07_ADMIN §9)
- Empty period → illustration, not zero (BR-DASH-004)

### 13.4 성능 SLA

| Metric | Target |
|--------|--------|
| First paint | < 2s |
| overview p95 | < 500ms (cache hit) |
| Chart p95 | < 1s |
| Aggregator batch | < 5s total |
