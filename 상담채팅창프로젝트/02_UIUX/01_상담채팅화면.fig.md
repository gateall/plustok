## 1. 목적 (Purpose)

### 1.1 설계 목표

카카오톡처럼 **익숙한 채팅 UX**를 제공하면서, **CRM**과 **AI Assistant**가 동일 화면에 통합된 상담원 전용 워크스페이스를 구현한다.

> 상담원이 **채팅 하나**만으로 상담·AI 추천·CRM·후속 업무를 처리할 수 있게 설계한다.

### 1.2 핵심 UX 원칙

| 원칙 | 설명 |
|------|------|
| Familiarity | 메신저 앱과 동일한 메시지 버블·입력창 패턴 |
| Zero Context Switch | CRM/FAQ/견적을 별도 탭 전환 없이 우측 AI 패널에서 처리 |
| 1-Click AI | `RecommendationCard` 클릭 → `InputField` 삽입 → 전송 |
| Real-time First | WebSocket 우선, REST는 히스토리·AI fetch |
| Responsive | PC 3패널 → 모바일 탭 전환 |

### 1.3 성공 기준

- 상담원 교육 시간 30분 이내 (카카오톡 사용자 기준)
- AI 추천 → 전송까지 3클릭 이내
- PC·태블릿·모바일 동일 기능 (레이아웃만 변경)

## 5. DB (데이터베이스 참조)

| 컬럼 | 타입 | 설명 |
|------|------|------|

| sender_id | VARCHAR(36) | - |
| content | TEXT | 메시지 본문 |
| attachment_url | VARCHAR(500) | nullable |

#### customers (고객)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | VARCHAR(36) | PK |

| tags | JSON | ["신규","고가","긍정"] |

| created_at | DATETIME | - |

#### ai_recommendations (AI 추천)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | VARCHAR(36) | PK |

#### chat_read_status (읽음 표시)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | BIGINT | PK |
| room_id | VARCHAR(36) | FK |

| reader_id | VARCHAR(36) | - |
| read_at | DATETIME | ✓✓ 시점 |

### 5.2 ER 관계 (요약)

```
customers 1 ── N chat_rooms 1 ── N chat_messages
chat_rooms 1 ── N ai_recommendations
chat_messages 1 ── N chat_read_status
```

### 6.1 REST API

#### GET /api/chats/rooms — 상담목록

**Query Parameters:**

| Param | Type | 설명 |
|-------|------|------|
| status | string | `new`, `active`, `closed` (comma-separated) |
| search | string | 고객명·문의유형 검색 |
| page | int | default 1 |
| limit | int | default 20, max 50 |
| sort | string | `updated_at:desc` (default) |

**Response 200:**

```json
{
  "success": true,
  "data": {
    "rooms": [
      {
        "id": "room-uuid-1",
        "customer": { "id": "cust-1", "name": "홍길동", "phoneMasked": "010-1234-****" },
        "inquiryType": "인터넷 가입",
        "status": "new",
        "unreadCount": 2,
        "contractProbability": 87,
        "updatedAt": "2026-07-21T14:30:00+09:00"
      }
    ],
    "pagination": { "page": 1, "limit": 20, "total": 45 }
  },
  "timestamp": "2026-07-21T14:35:00+09:00"
}
```

**UI 바인딩:** `ChatList` items

#### GET /api/chats/{id}/messages — 메시지 목록

**Path:** `{id}` = room_id

## 7. Business Rule (비즈니스 규칙)

### 7.1 읽음 표시 규칙

```
메시지 수신 (WebSocket message:receive)
    ↓
자동 ✓ 표시 (delivered) — chat_read_status INSERT (delivered_at)
    ↓
상담원이 채팅창 클릭 OR room 포커스
    ↓
PUT /api/chats/{id}/read 호출
    ↓
✓✓ 표시 (read) — read_at 기록
```

| 규칙 | 상세 |
|------|------|
| BR-READ-001 | 메시지 수신 즉시 ✓ (delivered) 표시 |
| BR-READ-002 | room 활성화(클릭/포커스) 시 ✓✓ (read) |
| BR-READ-003 | 자동 read 처리 금지 — 반드시 사용자 액션 |
| BR-READ-004 | closed room은 read API skip |

### 7.2 입력 중 (Typing) 규칙

| 규칙 | 상세 |
|------|------|
| BR-TYPE-001 | InputField `onInput` → `typing:start` emit |
| BR-TYPE-002 | 3초간 입력 없음 → `typing:stop` |
| BR-TYPE-003 | 메시지 전송 → 즉시 `typing:stop` |
| BR-TYPE-004 | TypingIndicator는 상대방에게만 표시 |

### 7.3 AI 추천 트리거

```
고객 메시지 POST/WS 수신
    ↓
Backend: ai_recommendations status=pending
    ↓
AI Router (Claude → Failover)
    ↓
2초 이내 completed → Client ai:update
    ↓
RecommendationCard 최대 3개 표시
    ↓
상담원 클릭 → InputField 삽입 (source=ai_recommendation)
```

| 규칙 | 상세 |
|------|------|
| BR-AI-001 | 고객 메시지마다 AI 분석 트리거 |
| BR-AI-002 | 추천답변 최대 3개 |
| BR-AI-003 | 동일 room 1분 내 중복 AI 호출 debounce |
| BR-AI-004 | Failover: [MASTER Rule-001](../00_PROJECT_MASTER.md) |

### 7.4 상담 종료 프로세스

```
ActionButton "상담종료" 클릭
    ↓
1. 확인 모달 ("상담을 종료하시겠습니까?")
    ↓
2. chat_rooms.status = 'closed', closed_at = NOW()
    ↓
3. AI 상담요약 생성 → CRM 저장
    ↓
4. 후속일정 제안 (V2.0: 일정 API)
    ↓
5. (선택) 고객 피드백 요청 메시지 전송
    ↓
6. ChatList StatusBadge → [종료]
```

### 7.5 상담방 배정

| status | 전환 조건 |
|--------|----------|
| new → active | 상담원이 room 선택 + 첫 응답 |
| active → closed | 상담종료 ActionButton |
| new → closed | 24h 무응답 자동 종료 (system) |

## 8. AI Rule (AI 규칙)

> 상위 규칙: [00_PROJECT_MASTER PART 7](../00_PROJECT_MASTER.md)

### 8.1 추천답변 생성

| 항목 | 값 |
|------|-----|
| Primary Prompt | `PROMPT_RECOMMEND_v1.0` |
| Prompt 내용 | "고객 질문과 대화 맥락을 바탕으로 상담원이 전송할 최선의 답변 3개를 JSON 배열로 제시하시오" |
| Failover | Claude → GPT → Gemini → Grok |
| Cache | Redis 1시간 (roomId + lastMessageId) |
| Output | `ai_recommendations.content.recommendations[]` |

### 8.2 FAQ 검색

```
고객 질문 → 임베딩 (text-embedding-3-small)
    ↓
FAQ 벡터 DB cosine similarity
    ↓
상위 3개 → AIPanelCard type="faq"
```

### 8.3 계약확률 계산

| 입력 | 가중치 |
|------|--------|
| 대화 내용 (구매 의향 키워드) | 40% |
| customers.tags (신규/기존) | 20% |
| sentiment (긍정 +, 부정 -) | 20% |
| inquiry_type (카테고리별 base score) | 20% |

- 출력: 0~100 정수, `AIPanelCard` 별점 (20점당 ★1)
- 70+ : "높음 - 우선 대응" 라벨
- 40~69: "보통"
- 0~39: "낮음"

### 8.4 고객분석

| 분석 항목 | 출력 |
|-----------|------|
| 감정 | positive / neutral / negative |
| 의도 | purchase / inquiry / complaint |
| 분류 | 신규 / 기존 / 위험 |
| 태그 | customers.tags JSON 자동 갱신 |

## 9. Exception (예외 처리)

### 9.1 UI 예외 매트릭스

| 상황 | UI 표시 | 사용자 액션 | 재시도 |
|------|---------|------------|--------|
| 메시지 전송 실패 | MessageBubble 옆 ⚠️ + "재시도" | ActionButton retry | 자동 1회 후 manual |
| AI 응답 지연 (2~5초) | AIPanelCard "분석 중..." | 대기 | - |
| AI 응답 지연 (5초+) | "AI 분석 중... 잠시만 기다려주세요" | 대기 | Backend Failover |
| AI 응답 실패 (all failed) | "AI 분석 불가" + 회색 패널 | 수동 답변 | "다시 시도" 버튼 |
| WebSocket 끊김 | Header 하단 배너 "재연결 중..." | 자동 | exponential backoff |
| WebSocket 재연결 실패 (30s) | "연결 끊김. [새로고침]" | 페이지 refresh | manual |
| 파일 업로드 실패 | FileUpload 빨간 border + 오류 메시지 | 재선택 | manual |
| 401 Unauthorized | 로그인 페이지 redirect | 재로그인 | - |
| 429 Rate Limit | Toast "요청이 많습니다. 잠시 후 다시 시도" | 60s 대기 | auto |

### 9.2 오프라인 메시지 큐

- WebSocket disconnect 중 전송 시도 → LocalStorage queue
- reconnect 성공 → queue 순차 POST
- queue 100건 초과 → 오래된 항목 drop + 경고

### 9.3 Error Code 매핑

| code | HTTP | UI Message |
|------|------|------------|
| MSG_SEND_FAILED | 500 | 메시지 전송에 실패했습니다 |
| AI_ALL_FAILED | 503 | AI 분석을 사용할 수 없습니다 |
| FILE_TOO_LARGE | 400 | 파일 크기는 10MB 이하여야 합니다 |
| ROOM_NOT_FOUND | 404 | 상담방을 찾을 수 없습니다 |
| FORBIDDEN | 403 | 접근 권한이 없습니다 |
