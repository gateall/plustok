### PART 5. AI Strategy (2~3페이지)
**목적:** AI가 무엇을 하는가 (매우 중요)

**AI 역할 10가지:**

```
1. 상담요약 (Summarization)
   └─ 고객 대화를 간단하게 요약
   └─ 상담원이 빠르게 상황 파악

2. 고객분석 (Customer Analysis)
   └─ 고객 배경, 관심사, 구매 의사 분석
   └─ 고객 프로필 자동 작성

3. 감정분석 (Sentiment Analysis)
   └─ 고객 감정 파악 (긍정/중립/부정)
   └─ 불만 고객 즉시 발견

4. 계약확률 (Contract Probability)
   └─ 고객의 구매 가능성 0~100점 산출
   └─ 우선순위 자동 결정

5. 답변추천 (Answer Recommendation)
   └─ 상담원이 답할 내용 제시
   └─ 1클릭으로 전송

6. FAQ 검색 (FAQ Search)
   └─ 질문과 유사한 FAQ 자동 검색
   └─ 해답 제시

7. 문서검색 (Document Search)
   └─ 가격표, 상품 자료, 계약서 검색
   └─ 빠른 참조 가능

8. 상품추천 (Product Recommendation)
   └─ 고객 문의에 맞는 상품 추천
   └─ Cross-selling 기회 제시

9. 일정생성 (Appointment Generation)
   └─ 상담 후 후속 일정 자동 생성
   └─ 캘린더에 등록

10. CRM 기록 (CRM Recording)
    └─ 상담 내용 자동으로 CRM에 저장
    └─ 수작업 제거
```

**AI 실행 흐름:**

```
고객 메시지
    ↓
AI Router (활성 AI 선택)
    ↓
Claude 호출 (기본)
    ↓ 실패 (timeout/rate limit/error)
GPT 호출
    ↓ 실패
Gemini 호출
    ↓ 실패
Grok 호출
    ↓
응답 반환 (성공)
    ↓
상담원 화면에 표시 (추천답변, 계약확률, FAQ 등)
    ↓
상담원 클릭 → 고객에게 전송
    ↓
CRM 자동 저장
```

### PART 7. AI Rule (1~2페이지)
**목적:** AI 사용 규칙 (매우 중요)

**포함 내용:**

```
Rule-001: AI Router Failover
┌──────────────────────────────────────────┐
│ 활성 AI가 실패하면 자동으로 다음 AI로  │
├──────────────────────────────────────────┤
│ 1단계: Claude (기본)                     │
│ 2단계: OpenAI GPT (Claude 실패 시)      │
│ 3단계: Google Gemini (GPT 실패 시)      │
│ 4단계: xAI Grok (Gemini 실패 시)        │
│ 5단계: 실패 응답 (모두 실패 시)         │
│                                          │
│ 타이아웃: 10초                          │
│ 재시도: 최대 4회                        │
│ 로그: ai_failover_log에 기록            │
└──────────────────────────────────────────┘

Rule-002: Prompt Versioning
- 모든 Prompt는 버전 관리 (v1.0, v1.1, v1.2, ...)
- 변경 이력 기록 (날짜, 변경자, 변경 내용)
- Prompt 테이블에 저장
- Rollback 가능하도록 설계

Rule-003: API Key Management
- 환경변수로 관리 (.env 파일)
- 코드에 하드코딩 금지
- 각 AI별로 별도 저장
- 정기적 로테이션

Rule-004: Response Handling
- API 응답 타입 표준화 (JSON)
- 에러 응답: {success: false, error: "...", code: "..."}
- 성공 응답: {success: true, data: {...}}
- 항상 타임스탬프 포함

Rule-005: Rate Limiting
- IP당 분당 100 요청 제한
- 사용자당 분당 50 요청 제한
- 초과 시 429 응답
- Redis로 관리
```

- 상담원이 채팅 하나만으로 모든 업무 처리 가능하게 설계

### 2. 범위(Scope)
- PC 화면 (1440px 기준)
- 태블릿 화면 (768px 기준)
- 모바일 화면 (375px 기준)
- 레이아웃: 3패널 (PC), 탭 전환 (모바일)

### 3. 요구사항
- 실시간 메시지 (WebSocket)
- 파일/이미지 전송
- 읽음 표시
- 입력 중 표시
- AI 추천 기능
- 반응형 디자인

### 5. DB
참조할 테이블:
- `chat_rooms` - 상담방
- `chat_messages` - 메시지
- `customers` - 고객 정보
- `ai_recommendations` - AI 추천
- `chat_read_status` - 읽음 표시

### 6. API
필요한 API 엔드포인트:
- `GET /api/chats/rooms` - 상담목록
- `GET /api/chats/{id}/messages` - 메시지 목록
- `POST /api/chats/{id}/messages` - 메시지 전송
- `GET /api/ai/recommendations/{id}` - AI 추천
- `PUT /api/chats/{id}/read` - 읽음 표시

### 7. Business Rule

```
읽음 표시 규칙:
- 메시지 수신 즉시 표시 (✓)
- 메시지 클릭하면 더블체크 (✓✓)
- 자동으로 표시 안 함

입력 중 표시:
- 사용자가 입력 시작하면 "입력 중..." 표시
- 3초간 입력 없으면 사라짐
- 전송 완료 시 사라짐

AI 추천 트리거:
- 고객 메시지 전송 즉시
- 2초 내 추천 완료
- 실패 시 "계산 중..." 표시
- 최대 3개 추천 표시

상담 종료 프로세스:
- "상담종료" 버튼 클릭
- 자동으로:
  1. 상담요약 생성
  2. CRM 저장
  3. 후속일정 제안
  4. 피드백 수집
```

### 8. AI Rule

```
추천답변 생성:
- Claude Prompt: "이 질문에 대한 최선의 답변 3개를 제시하시오"
- 실패 시 GPT 호출
- 캐싱: 1시간

FAQ 검색:
- 고객 질문 임베딩
- FAQ 데이터베이스와 유사도 계산
- 상위 3개 표시

계약확률 계산:
- 고객 정보 + 대화 내용 분석
- 0~100점 산출
- 실시간 업데이트

고객분석:
- 감정, 의도, 배경 파악
- 신규/기존/위험 고객 분류
- 자동 태그 생성
```

### 9. Exception

```
오류 처리:
- 메시지 전송 실패: 재시도 버튼 표시
- AI 응답 지연(5초): "분석 중..." 표시
- AI 응답 실패: "AI 분석 불가" 표시
- 네트워크 끊김: "재연결 중..." 표시 + 자동 재연결
- 파일 업로드 실패: 오류 메시지 + 재시도 옵션
```
