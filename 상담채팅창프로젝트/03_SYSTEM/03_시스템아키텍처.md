### 2.3 Nginx Upstream 라우팅

```nginx
upstream acep_backend {
    least_conn;
    server acep-backend-1:8081;
    server acep-backend-2:8081;
}

upstream acep_chat {
    ip_hash;  # WebSocket sticky session
    server acep-chat-server-1:3001;
    server acep-chat-server-2:3001;
}

location /api/v1/ {
    proxy_pass http://acep_backend;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Request-Id $request_id;
}

location /socket.io/ {
    proxy_pass http://acep_chat;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 86400;
}
```

## 5. AI Router 아키텍처

### 5.1 Failover Chain (Rule-001)

```
┌──────────────────────────────────────────────────────────┐
│                      AI Router Service                    │
├──────────────────────────────────────────────────────────┤
│  1. Load ai_provider_config ORDER BY priority             │
│  2. Load ai_prompts WHERE role=? AND is_active=1          │
│  3. Check Redis cache (roomId + messageHash)               │
│  4. FOR EACH provider:                                   │
│       TRY call (timeout 10s)                               │
│       ON fail → ai_failover_log + next provider            │
│  5. Normalize JSON → ai_recommendations                    │
│  6. ai_logs INSERT                                       │
│  7. Redis PUBLISH ai:done                                  │
└──────────────────────────────────────────────────────────┘
         │              │              │              │
    ┌────▼────┐   ┌────▼────┐   ┌────▼────┐   ┌────▼────┐
    │ Claude  │   │  GPT    │   │ Gemini  │   │  Grok   │
    │ Primary │   │ Fail 2  │   │ Fail 3  │   │ Fail 4  │
    └─────────┘   └─────────┘   └─────────┘   └─────────┘
```

### 5.2 AI 호출 격리

- AI Router는 **별도 Worker Process** (PHP: queue consumer, Node: BullMQ)
- REST API thread blocking 방지
- Room당 rate limit: Redis `rl:ai:room:{id}` (Rule-005)

## 6. 보안 아키텍처

### 6.1 Security Layers

```
┌─────────────────────────────────────────────────────────┐
│ Layer 1: Network — HTTPS/TLS 1.3, HSTS, Firewall         │
├─────────────────────────────────────────────────────────┤
│ Layer 2: Edge — Nginx rate limit, CORS whitelist       │
├─────────────────────────────────────────────────────────┤
│ Layer 3: Auth — JWT (24h) + Refresh (7d HttpOnly)      │
├─────────────────────────────────────────────────────────┤
│ Layer 4: RBAC — agent/admin/operator role matrix       │
├─────────────────────────────────────────────────────────┤
│ Layer 5: Data — PII AES-256, Prepared Statement        │
├─────────────────────────────────────────────────────────┤
│ Layer 6: Audit — audit_logs, ai_logs (90일)            │
└─────────────────────────────────────────────────────────┘
```

### 6.2 JWT + RBAC

| Role | Scope |
|------|-------|
| agent | assigned rooms + new (unassigned) |
| admin | all rooms, admin APIs |
| operator | read-only + system config |
| customer | own room only (widget token) |

**Room IDOR 방지:**

```php
// ChatService::assertRoomAccess($roomId, $jwtSub, $role)
// 1. chat_rooms.agent_id = sub OR status=new OR role=admin
// 2. audit_logs on forbidden attempt
```

### 6.3 WebSocket Security

- wss:// only (TLS)
- JWT in handshake `auth.token`
- room:join 시 server-side room access 재검증
- Origin header whitelist

### 6.4 PII 처리

| 단계 | 처리 |
|------|------|
| Input | validate → encrypt (AES-256-GCM) |
| Storage | ciphertext in MariaDB |
| Output | decrypt → mask → JSON response |
| Log | PII 제외, request_hash only |

## 7. 확장성 (Scalability)

### 7.1 1,000 동시 WebSocket 목표

| 항목 | 전략 | 목표 |
|------|------|------|
| Chat Server | horizontal scale (2→4 replicas) | 250 conn/instance |
| Sticky Session | Nginx ip_hash / cookie | reconnect same room |
| Redis Pub/Sub | cross-instance broadcast | all nodes sync |
| Connection limit | ulimit, somaxconn tuning | 65535 |
| Memory | 1 conn ≈ 10KB → 1K = 10MB | negligible |

### 7.2 Chat Server Scale-out

```
                    Nginx (ip_hash)
                         │
         ┌───────────────┼───────────────┐
         │               │               │
    Chat Server 1   Chat Server 2   Chat Server 3
         │               │               │
         └───────────────┼───────────────┘
                         │
                    Redis Pub/Sub
                    (acep:events channel)
```

### 7.3 Backend Scale-out

- **Stateless:** JWT only, no server session
- **DB connection pool:** max 20/instance, 2 instances = 40
- **Read replica:** MariaDB replica for GET-heavy (ChatList)
- **AI Worker:** 별도 scale (CPU/IO bound)

### 7.4 Performance SLA (MASTER PART 8)

| Metric | Target | Architecture Support |
|--------|--------|---------------------|
| WS latency | 0.1s | Chat Server direct relay |
| AI display | 2s | async worker + ai:update push |
| REST p95 | 1s | index, Redis cache |
| Page load | 3s | static CDN, code split |

### 7.5 Capacity Planning

| Load | Config |
|------|--------|
| 100 WS | 1 chat-server, 1 backend |
| 500 WS | 2 chat-server, 2 backend |
| 1,000 WS | 4 chat-server, 2 backend, Redis sentinel |
| 10,000 msg/min | MariaDB write batch, partition ai_logs |

## 11. 데이터 흐름 요약

| Flow | Path |
|------|------|
| ChatList load | Client → GET /api/v1/chats/rooms → MariaDB |
| Message history | Client → GET /api/v1/chats/{id}/messages |
| Real-time msg | Client → POST messages + WS message:receive |
| AI panel | Backend worker → ai_recommendations → WS ai:update |
| Read status | Client → PUT read → WS read:update |
| File upload | Client → POST /api/v1/files/upload → S3/local |
| Auth | POST login → JWT → WS handshake |

## 12. 장애 대응 (Failure Modes)

| Failure | Detection | Fallback |
|---------|-----------|----------|
| Chat Server down | health check | WS reconnect 다른 instance |
| Backend down | 502, health | queue retry, error toast |
| MariaDB down | connection error | 503, read replica (V2.0) |
| Redis down | cache miss | DB direct, rate limit off (warn) |
| All AI failed | AI_ALL_FAILED | manual reply, retry button |
| Claude down | failover log | GPT → Gemini → Grok |

### RTO/RPO (MASTER 8.3)

| Metric | Target |
|--------|--------|
| RTO | 4 hours |
| RPO | 24 hours (daily backup) |
