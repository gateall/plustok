# SPEC — 기능 명세서 (V1.0)

대상 독자: 구현 에이전트. 여기 적힌 동작은 **그대로 구현**한다. 값·문구는 변경 시 이 문서를 먼저 수정한다.

## A. 상담폼 (Front-End, 임베드)

### A-1. 배포 방식

각 사이트는 아래 한 줄만 삽입한다. `site` 값(`site_code`)으로 브랜드·상품·질문셋·페르소나를 자동 로드한다.

```html
<div id="plustok-form"></div>
<script src="https://plustok.mycafe24.com/embed/embed.js?site=lg15441644" async></script>
```

- `embed.js`는 `#plustok-form`에 폼을 렌더한다.
- 폼 설정(브랜드명, 첫인사, 상품 목록, 동적 입력 항목)은 `embed/form.php?site=<code>`가 JSON으로 반환한다.
- 직접 삽입용 정적 HTML 스니펫은 [부록 A-9] 참고(임베드가 불가한 사이트용).

### A-2. 폼 흐름 (5단계)

```
① 신청 상품 → ② 상담 정보 → ③ 추가 요청 → ④ 개인정보 동의 → ⑤ 신청하기 → 완료(접수번호)
```

모바일 우선. 진행 상태(Step UI) 표시. 첫 화면은 **버튼 선택형**(채팅형 질문 지양)으로 5초 내 완료 유도.

### A-3. Step 1 — 신청 상품 (site_code별로 다름)

### A-4. Step 2 — 상담 정보

**공통 입력**

| 필드 | 필수 | 비고 |
|---|---|---|
| 이름 (`customer_name`) | ✅ | |
| 휴대폰 (`phone`) | ✅ | 숫자 키패드 자동, 하이픈 자동 처리 |
| 회사명 (`company`) | | |
| 이메일 (`email`) | | 형식 검증 |
| 지역 (`region`) | | 시/도 |
| 설치주소 (`address`) + 우편번호(`zipcode`) | | V2.0에서 주소검색 API |
| 희망 상담시간 (`preferred_time`) | | 오늘 / 이번주 / 이번달 / 직접입력 |

**상품별 동적 입력** (선택 상품에 따라 표시)

| 상품 | 추가 입력 |
|---|---|
| 기업인터넷 | 인터넷 속도: 100M / 500M / 1G / 2.5G / 5G / 10G |
| 070전화 | 회선수 · 대표번호 여부 · 녹취서비스 · 단말기 |
| 대표번호 | 번호 유형: 1544 / 1644 / 1661 / 1800 / 기타 |
| 홈페이지 | 유형: 기업형 / 쇼핑몰 / 랜딩페이지 / 유지관리 |
| 판촉물 | 수량 · 예산 · 행사일 · 납기일 |
| 이사 | 출발지 · 도착지 · 이사날짜 · 평수 |

> 상품별 입력값은 개별 컬럼으로 두지 않고 `consults.detail_json`(JSON)에 저장한다. [`DB.md`](DB.md) 참고.

### A-5. Step 3 — 추가 요청

- 자유 서술 텍스트 (`memo`)

### A-6. Step 4 — 개인정보 동의

- 체크박스: "개인정보 수집 및 이용에 동의합니다." (`agree`, 필수 = true여야 제출 가능)
- [보기] 링크로 약관 모달 표시

### A-7. Step 5 — 파일 첨부(선택)

- 사업자등록증 / 사진 / 견적서 / 도면 / PDF
- `POST /api/v1/upload.php` 사용. 허용 확장자·용량은 [`STYLEGUIDE.md`] 보안 규칙 따름.

### A-8. 완료 화면

```
접수가 완료되었습니다.
접수번호: C202607170001
담당자가 연락드립니다.
```

- 접수번호 형식: `C` + `YYYYMMDD` + 4자리 일련번호 (당일 0001부터).

### A-9. 부록 — 직접 삽입 HTML 스니펫

임베드 스크립트를 못 쓰는 사이트는 정적 폼을 삽입하고, 제출을 `POST /api/v1/consult.php`로 보낸다.
필수 hidden 필드: `site_code`, `api_key`(공개 키가 아닌 **서버측 프록시** 경유 권장 — 클라이언트에 시크릿 노출 금지).
→ 상세는 [`API.md`](API.md) "브라우저에서의 API Key 취급" 참고.

### A-10. 모바일 최적화 규칙

- 큰 입력창/버튼, 터치 영역 최소 44px
- 전화/숫자 입력은 `inputmode="numeric"` / `type="tel"`
- Step 진행 표시, 자동 스크롤, 실시간 입력값 검증
- 임시 저장(localStorage) — 선택 구현

## B. 관리자 CRM (`/admin/`)

로그인(세션) 후 접근. 권한별 메뉴 노출은 [C. 권한] 참고.

### B-1. 대시보드
- 요약 카드: 전체 상담 / 신규 상담 / 상담 진행중 / 계약 완료 / 이번 달 예상매출(선택)
- 사이트별 상담 현황(건수), 최근 상담 목록(실시간, 새로고침 없이 자동 표시 — 폴링 허용)

### B-2. 고객관리 (`customers`)
- 목록: 고객번호 · 이름 · 연락처 · 회사 · 사업부/브랜드 · 최근 상담일 · 상담 건수
- 상세: 기본정보 · 상담 이력 · 계약 이력(V2) · 메모 · 첨부파일
- **중복 고객 판단 기준: 전화번호(`phone`)**. 동일 전화면 기존 고객에 상담 연결.

### B-3. 상담관리 (`consults`)
- 목록: 상담번호 · 접수일 · 사이트 · 상품 · 고객명 · 연락처 · 담당자 · **상태**
- 필터: 사이트별 / 상품별 / 담당자별 / 상태별 / 기간
- 상세: 고객정보 · 상담내용 · 상품별 상세(detail_json) · 첨부 · 상태변경 · 담당자 배정 · 메모
- **상태 변경 시 `consult_history`에 자동 기록.**

### B-4. 사이트관리 (`sites`)
- 목록/등록: site_code · 사이트명 · 도메인 · **브랜드** · **사업부** · API Key · 사용여부
- API Key **발급/재발급** 기능. (한 브랜드에 도메인 여러 개면 행을 여러 개 등록)

### B-5. 상품관리 (`products`)
- 브랜드별 상품(카테고리) 등록/사용여부 토글. 상담폼 Step1 옵션의 원천.

### B-6. 담당자관리 (`managers`)
- 등록/수정: 로그인ID · 이름 · 연락처 · **권한(role)**. 비밀번호는 `password_hash()`.

### B-7. 통계
- 기간별 / 사이트별 / 상품별 / 담당자별 / 상태별 상담 건수. 일별 추이 차트.

### B-8. 설정
- 회사정보 · API Key 관리 · 알림 설정 · (V1.5+) 외부 연동 키. **로그관리**(작업 로그 조회).

### B-9. 파일관리
- 업로드된 첨부(사업자등록증/견적서/도면 등) 조회·다운로드. 접근 권한 제한.

## C. 상담 상태 흐름 (status)

```
신규(접수) → 진행중 → 상담중 → 견적발송 → 계약완료 → 설치완료
                                   └─▶ 보류 / 취소 (어느 단계에서든 전환 가능)
```

| 코드 | 라벨 |
|---|---|
| `new` | 신규(접수) |
| `progress` | 진행중 |
| `consulting` | 상담중 |
| `quoted` | 견적발송 |
| `contracted` | 계약완료 |
| `installed` | 설치완료 |
| `hold` | 보류 |
| `canceled` | 취소 |

모든 상태 변경은 `consult_history`에 (이전상태, 변경상태, 담당자, 시각)으로 남긴다.

| role | 범위 |

## E. 상담 접수 처리 규칙 (서버측)

`POST /consult` 수신 시 순서대로 수행:

1. API Key 검증 → `site_code`로 사이트 확인 (없거나 비활성 → 401/403)
2. 필수값 검증(`customer_name`, `phone`, `agree=true`)
3. **고객 중복 확인**(phone 기준) → 없으면 `customers` 신규 등록, 있으면 연결
4. 상담번호 생성(`C{YYYYMMDD}{NNNN}`)
5. `consults` insert (site_id, product_id, customer_id, status=`new`, detail_json, memo)
6. `consult_history` 최초 상태(`new`) 기록
7. (첨부가 있으면 upload로 별도 처리 후 `attachments` 연결)
8. 관리자 알림(대시보드 표시 / V1.5+ 푸시·SMS·카톡)
9. 응답 반환(`consult_no`)

> V1.0에서 AI 요약(`ai_summary`)은 **비워둔다**(자리만 유지). OpenAI 연동은 V1.5.
